# 本机交接手册与环境配置设计

## 目标

为下一位维护者提供与当前代码一致、可执行的交接手册，并将本机开发环境配置为 PostgreSQL、Redis、126 邮箱和本地文件存储。真实凭据只保存在未纳入版本控制的 `backend/.env` 中。

## 范围

- 重写根目录 `HANDOVER.md`，记录项目边界、真实完成度、依赖服务、初始化、启动、验证、故障排查、安全事项和后续工作。
- 修复根目录 `.gitignore`，至少忽略环境文件、Python/Node 依赖、缓存、构建产物、本地上传和编辑器文件。
- 更新 `backend/.env.example`，使变量名与 `backend/app/core/config.py` 一致，并提供无秘密的本机示例。
- 配置 `backend/.env`，使用本机 PostgreSQL `postgres:postgres@localhost:5432/turtle_soup`、Redis `localhost:6379/0`、本地上传和 126 SMTP。
- 为 SMTP 增加显式 SSL 开关，使 `smtp.126.com:465` 可被当前邮件服务使用。

不在本次范围内：安装或初始化 PostgreSQL/Redis、创建生产部署配置、修复与环境配置无关的业务缺陷、启用当前认证路由中尚未调用的邮件发送流程。

## 配置设计

`Settings` 新增布尔变量 `SMTP_USE_SSL`。启用时邮件服务使用 `smtplib.SMTP_SSL`；关闭时沿用普通 SMTP 并调用 `STARTTLS`。本机 `.env` 使用 SSL 端口 465，发件地址与 SMTP 用户一致。

对象存储在本机显式关闭，上传写入 `backend/storage`。应用地址固定为 `http://localhost:10000`。JWT 密钥生成随机高熵值，不使用示例默认值。

## 安全设计

- `.env` 必须被 Git 忽略，权限设置为 `0600`。
- 手册、示例配置、测试输出和最终说明不得包含 SMTP 授权码或 JWT 密钥。
- 验证配置时只报告变量是否设置，不输出真实值。
- 由于授权码已通过会话提供，若其曾被复制到其他公开位置，应在 126 邮箱后台轮换。

## 文档结构

交接手册按维护者实际接手顺序组织：项目结论、技术与目录、功能状态、环境要求、首次初始化、环境变量、启动与访问、验证命令、邮件与上传说明、已知问题、排障、后续优先级和安全检查。

手册明确区分“代码存在”“已测试”“端到端可用”，避免把占位页面或未联调路由描述为已完成。

## 验证

- 检查 `.gitignore` 确实命中 `backend/.env`。
- 使用后端虚拟环境加载 `Settings`，断言本机服务地址、SMTP SSL 和本地存储配置正确，但不打印秘密。
- 对 SMTP 连接逻辑增加单元测试，覆盖 SSL 与 STARTTLS 两条分支。
- 运行相关后端测试、Python 编译检查和前端生产构建。
- 网络可用时，仅进行 SMTP 登录/连接检查；不擅自向外部地址发送测试邮件。

## 失败处理

缺少 PostgreSQL、Redis 或数据库时，手册给出明确检查与创建命令。SMTP 网络验证若受沙箱或网络限制，将记录为未验证项，不把它误报为成功。现有测试或构建失败时，区分本次改动导致的问题与仓库已有问题。
