# 海龟汤核心闭环设计

日期：2026-08-07

## 目标

在不全面重写项目的前提下，修复阻断应用启动和联调的数据模型/API 契约错误，并完成可真实使用的海龟汤核心闭环：详情浏览、汤底揭示、评分、点赞、收藏、评论与一级回复。

本轮同时建立测试驱动、模块化的后端结构和可信的项目交接手册，为后续论坛、比赛、消息和管理模块提供可复用模式。

## 范围

### 包含

- 修复应用启动链路及海龟汤功能直接依赖中的导入、依赖和字段错位。
- 统一以 `backend/app/models/models.py` 中的 SQLModel 模型为数据事实来源。
- 实现海龟汤详情读取和受控汤底揭示。
- 实现 1 至 10 分、0.5 分步进的新增和修改评分。
- 实现幂等的点赞、取消点赞、收藏和取消收藏。
- 实现评论列表、发布、一级回复和作者软删除。
- 实现详情页及可复用的评分、互动和评论组件。
- Redis 不可用时，排行榜读取和更新降级到数据库路径。
- 建立后端测试、前端组件测试、类型检查和构建验证。
- 重写 `HANDOVER.md`，只记录经代码或验证确认的状态。

### 不包含

- 无限层级评论、富文本评论和图片上传。
- WebSocket 实时通知、成就事件、比赛结算和 Elasticsearch。
- 全量重构认证、论坛、比赛、消息、社交和管理模块。
- 修复与本批启动链路或核心闭环无关、且不能被现有检查复现的问题。

## 架构

后端采用薄路由和显式业务层。现有模型继续集中维护，海龟汤功能按职责拆分：

- `api`：解析请求、注入当前用户与数据库会话、映射响应和 HTTP 状态。
- `services`：执行详情可见性、评分、互动和评论业务规则，并定义事务边界。
- `repositories`：封装 Soup、Rating、Like、Favorite、Comment 的查询和持久化。
- `schemas`：定义稳定的请求、响应和错误契约，不向前端暴露 ORM 对象。
- `policies`：集中处理账户状态、作者限制和黑名单交互限制。
- `cache`：封装排行榜 Redis 操作；缓存失败只影响性能，不影响写入成功或详情访问。

避免为每个简单查询创建抽象。Repository 只承载重复查询、并发敏感写入和跨表读取；纯计算函数保持独立并可直接单元测试。

## API 契约

### 详情

`GET /api/turtle-soups/{id}` 返回：

- 海龟汤基础字段、作者摘要、评分与互动计数。
- `solution`：仅作者、管理员、已全局公开或请求明确揭示时返回。
- `solution_available`：汤底是否存在且可被用户主动揭示。
- `is_solution_public`：作者是否已将汤底全局公开。
- 当前登录用户的 `my_rating`、`is_liked`、`is_favorited` 和 `can_manage`。

匿名用户允许使用查询参数主动揭示汤底。此动作只改变本次响应，不改变数据库公开状态。浏览量按一次详情请求计数。

### 评分

`PUT /api/turtle-soups/{id}/rating` 接收 `score`。评分范围为 1 至 10，且必须是 0.5 的倍数。同一用户对同一作品只有一条评分；重复提交更新原评分。作者不能给自己的作品评分。

响应返回当前用户评分、最新平均分、贝叶斯分和评分人数。

### 点赞与收藏

`PUT /api/turtle-soups/{id}/like` 和 `PUT /api/turtle-soups/{id}/favorite` 接收目标布尔状态。重复提交相同状态仍成功，响应返回最终状态及最新计数。

数据库为 `(user_uid, target_type, target_id)` 建立唯一约束。记录变更和聚合计数更新处于同一事务，计数不得低于零。

### 评论

- `GET /api/turtle-soups/{id}/comments`：分页返回顶级评论及一级回复。
- `POST /api/turtle-soups/{id}/comments`：发布顶级评论或通过 `parent_id` 回复。
- `DELETE /api/turtle-soups/{id}/comments/{comment_id}`：评论作者或管理员软删除。

回复目标必须属于同一个海龟汤，并且回复的父评论必须是顶级评论。已删除评论保留占位信息，避免破坏对话上下文。

## 权限与错误处理

匿名用户可以浏览、主动揭示汤底和查看评论。评分、点赞、收藏、评论和管理动作要求登录且账户状态允许互动。

黑名单策略复用统一 policy：任一方向存在阻断关系时，用户不能对对方作品互动或评论。作者、管理员和根用户的管理权限通过单一 policy 判定。

错误响应使用稳定的机器错误码和中文消息，例如 `SOUP_NOT_FOUND`、`SELF_RATING_FORBIDDEN`、`INTERACTION_BLOCKED` 和 `INVALID_RATING_STEP`。前端按错误码处理登录跳转或状态回滚，不解析中文字符串。

## 前端设计

详情页采用安静、工作型的响应式布局。桌面端主区域显示作者、谜面、汤底和评论，固定宽度侧栏显示评分和互动；移动端按谜面、操作、汤底、评论顺序单列排列。

汤底初始为遮罩区域，用户明确点击后请求揭示。作者额外拥有公开汤底操作。评分采用可键盘操作的 0.5 步进控件，并同步显示数值，避免仅依赖星形图标表达精度。

点赞和收藏使用图标按钮、明确的按下状态和 tooltip。前端先等待接口结果再更新最终状态；请求中禁用相应控件，失败时保留服务器确认前的状态。

评论编辑框限制长度并显示提交状态。回复只展示一级结构。空状态、加载骨架、无权限、404 和网络失败都有独立展示，不通过空白页面表示。

前端数据访问拆为 API 客户端、Pinia 状态和无状态展示组件。详情页负责编排，不直接拼接 URL 或解释后端 ORM 字段。

## 数据一致性与缓存

评分、点赞、收藏和评论计数在数据库事务内更新。唯一约束是并发去重的最终保障；服务层捕获唯一冲突后读取并返回最终状态。

排行榜缓存通过适配器访问。Redis 连接失败时记录结构化警告并使用数据库排序；评分写入不能因为缓存更新失败而回滚。缓存键包含版本，后续字段或算法变化可无冲突重建。

## TDD 与验证

每个行为遵循红、绿、重构：先写失败测试证明缺陷或需求，再做最小实现，通过后再整理结构。

后端测试覆盖：

- 应用可导入并注册海龟汤路由。
- 匿名、普通用户、作者和管理员的汤底可见性。
- 评分范围、半分步进、作者限制和修改评分后的聚合值。
- 点赞/收藏的幂等行为、唯一性和非负计数。
- 评论发布、一级回复、跨汤回复拒绝和软删除。
- 账户状态与黑名单限制。
- Redis 故障时排行榜降级。

前端测试覆盖：

- 详情加载、404、网络失败和空评论状态。
- 汤底揭示状态。
- 评分控件的鼠标和键盘操作以及 0.5 步进。
- 匿名交互引导登录。
- 点赞、收藏、评分请求期间状态和失败处理。

完成标准：后端测试全部通过，前端组件测试全部通过，Python 导入检查通过，TypeScript 类型检查通过，生产构建成功。验证命令和实际结果写入交接手册。

## 交接手册

重写后的 `HANDOVER.md` 包含：

- 真实技术栈、目录结构和模块边界。
- 已完成、部分完成和未实现功能，禁止用路由空壳作为“已完成”。
- 本地环境依赖、配置、数据库初始化和启动命令。
- 测试、类型检查和构建命令及最后验证结果。
- API 核心契约与权限规则。
- 已知风险、技术债和下一批推荐顺序。
- 许可证说明与项目授权限制。

## 风险与迁移

当前 API 大量使用不存在的旧类名和字段名，修复启动链路可能暴露认证等相邻模块的同类错误。本批只修复应用导入、认证依赖和海龟汤闭环所需的最小集合，并为其他模块在交接手册中记录明确状态。

模型新增唯一约束需要数据库迁移。项目目前没有 Alembic，本批会建立最小迁移基础或提供明确的开发数据库重建路径；不能仅依赖 `create_all` 修改现有表结构。

项目当前 Git 工作树的仓库根目录似乎位于项目目录之外，且没有历史提交。设计和实施不会删除或覆盖项目外的用户文件；提交能力需以实际 Git 权限为准。
