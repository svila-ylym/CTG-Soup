# 比赛封面、可修改评分与首页侧栏优化设计

## 目标

在版本 `1.5.0` 内完成四项相互配合的改进：比赛可上传并展示封面；用户可修改自己对海龟汤的评分；首页把原有大幅风景首屏压缩为 Banner，并在下方使用类似 Bilibili 内容首页的主次双栏；将指定的太阳/月亮动画开关完整接入现有主题状态并嵌入移动侧栏，同时优化侧栏布局与交互。

按用户要求不采用 TDD。实现完成后补充回归测试并运行现有测试、构建和关键浏览器验证。版本保持 `1.5.0`，不增加第三方依赖。

## 现状与根因

- 比赛正文已经能引用本人上传的 `UploadedAsset`，但比赛请求、响应和前端表单均没有独立封面引用，因此列表、详情和首页只能显示纯色卡片。
- 评分数据库表本身具有 `updated_at`，但评分接口发现已有记录就返回 `409 RATING_ALREADY_SUBMITTED`；详情页又以 `my_rating != null` 禁用滑块并隐藏提交按钮，形成后端和前端双重永久锁定。
- 首页风景区使用 `36rem` 至 `43rem` 的最小高度，并同时放置大标题、操作区和谜题卡片舞台，导致风景和 Hero 占据首屏视觉主导；首页还分别请求排行榜、首页文案和外部一言，首屏数据流分散。
- 现有主题工具已负责 `html.dark`、系统主题、持久化和 View Transition。直接粘贴用户提供的原生 JS 会产生第二套状态和存储键；直接粘贴通用 `*`/`body` CSS 会破坏 Vue 应用全局布局。提供的云朵 CSS 还缺少 `height` 后的分号。

## 方案选择

### 采用方案：受控配置引用 + 首页聚合接口

封面继续使用现有公共图片上传能力。API 接收显式的 `cover_asset_id`，验证资源属于比赛创建者且类型为图片，然后把经过验证的 `cover_asset_id` 与稳定公共 URL 写入比赛的 `custom_page_config`。响应提供一等字段 `cover_asset_id` 和 `cover_url`，前端无需理解内部配置结构。这样复用既有存储、权限和 CDN/本地 URL，且无需给 1.5.0 增加数据库列迁移。

首页新增公共轻量聚合响应，一次返回首页文案、最新比赛摘要和四条随机海龟汤摘要。响应只包含首屏需要的数据并使用短 TTL Redis 缓存；Redis 故障继续回退数据库。浏览器获得短期公共缓存头。首页不再依赖排行榜请求和第三方一言请求。

### 未采用方案一：Competition 新增数据库列

独立 `cover_asset_id` 外键在关系模型上更显式，但需要兼容 PostgreSQL/SQLite 的幂等迁移、部署顺序和旧数据回填。本次封面只是一项可选展示配置，现有 `custom_page_config` 已承担比赛页面图片配置，迁移成本高于收益。

### 未采用方案二：只在前端组合现有列表接口

前端可以分别获取比赛列表和海龟汤列表，但现有汤列表没有随机排序，且会返回首页不需要的完整结构并触发多次请求。该方案实现快但不利于加载体验，也无法稳定控制随机推荐与缓存。

## 比赛封面

`CompetitionCreate`/`CompetitionUpdate` 增加可空 `cover_asset_id`；`CompetitionResponse` 增加可空 `cover_asset_id` 和 `cover_url`。创建时缺省为无封面。更新时字段未出现则保留旧封面，显式传 `null` 才移除，兼容旧客户端。

服务端统一处理正文与封面资产：正文图片仍限定最多 20 张且必须属于当前用户；封面必须是当前用户的 `kind=image` 资产。客户端传入的 `custom_page_config.cover_url` 或同名内部值一律被服务端覆盖，防止伪造外部封面。比赛响应从服务端保存的受控配置导出封面字段。

前端新增单封面选择器，使用现有 `/api/uploads/images`，展示 16:7 预览、上传忙碌状态、错误和移除操作。创建、编辑表单都提交资产 ID；编辑页通过响应中的 ID/URL恢复预览。封面用于比赛列表、比赛详情头图和首页最新比赛卡片，无封面时显示由竞赛色生成的渐变占位，不产生破图或布局跳动。

## 可修改评分

评分接口继续使用 `PUT /api/turtle-soups/{id}/rating`，语义改为幂等 upsert。作品行锁保持同一作品评分写入串行：没有记录时创建；已有记录时更新 `score` 与 `updated_at`，不改变最初 `created_at`。随后重新计算 `avg_rating`、`rating_count` 并刷新未结算平均分比赛中的作品得分，最后在同一事务提交。

唯一约束仍防止同一用户产生两条评分。若并发插入触发约束，接口回滚保存点、重新读取已有记录并更新，而不是返回永久锁定冲突。作者给自己评分仍被禁止，分数仍限定 1 至 10 且步长为 0.5。

详情页滑块只在请求提交期间禁用。已有评分显示“当前评分，可随时调整”，分数未变化时禁用重复提交；发生变化后按钮显示“修改评分”。确认对话框根据首次评分或修改评分展示不同文案，不再宣称不可修改。成功后只用接口返回值更新本地平均分、人数和我的评分，避免整页重载。

## 首页信息架构与加载

顶部保留现有 SVG 风景和按中国时区变化的色彩，但高度压缩为约 `15rem` 至 `20rem` 的 Banner。Banner 仅保留品牌标题、轮播短文案和两个主要入口，移除占据大量空间的谜题便签舞台、滚动提示与外部一言请求。风景层仍是装饰性内容并遵守减少动态效果偏好。

Banner 下方是主内容双栏：桌面端左侧约 7/12，显示最新比赛的大卡片，包括封面、状态、名称、说明摘要、时间、标签/评分方式和参赛数量；右侧约 5/12，显示四条随机海龟汤推荐，采用紧凑两列或单列自适应卡片。移动端按最新比赛、推荐汤顺序堆叠。无比赛、无汤、加载中和失败都有尺寸稳定的骨架或可恢复空状态。

`GET /api/home/discovery` 返回：

- `lines: string[]`
- `latest_competition: HomeCompetitionSummary | null`
- `random_soups: HomeSoupSummary[]`

随机汤只来自 `published`/`revealed` 状态。后端使用短 TTL 公共 Redis 缓存，缓存内容不含登录用户状态；缓存失败时直接查库。响应设置短期 `Cache-Control`，减少返回首页时的等待。封面与图片使用原公共存储的长期不可变缓存策略。

## 主题开关与侧栏

新增独立 `ThemeToggle.vue`，保留用户给出的按钮层级、云朵、星星 SVG、太阳/月亮遮罩和陨石坑结构。组件以 `role="switch"`、动态 `aria-checked` 和动态中英文无关的中文 `aria-label` 暴露状态。点击仍调用项目的 `applyTheme()`，因此继续兼容 `theme_preference`、系统主题、登录用户设置和 View Transition；组件不直接维护第二份主题真相。

CSS 按组件作用域移植，修复云朵 `height` 后的缺失分号，并把不适合侧栏的 `120px` 基准缩放为可用尺寸。不会复制用户示例的全局通配 reset、`body` 居中/固定高度或教程链接样式。提供键盘焦点、悬停、减少动态效果和暗色状态。

桌面导航用该组件替换原月亮/太阳图标按钮；移动侧栏在账号信息之后设置独立“外观”卡片，将组件完整放入卡片右侧，移除旧的文字主题按钮。多个实例使用不同 ID，避免重复 DOM ID。

侧栏继续从右侧进入，但改进为圆角玻璃面板、清晰分区、稳定安全区内边距和更明显的当前项状态。打开时聚焦关闭按钮，关闭后恢复到菜单触发按钮；路由变化、遮罩点击和 Escape 仍关闭，并保持 body 滚动锁正确恢复。

首页初始化前在 `index.html` 中增加与现有 `theme_preference` 兼容的极小内联脚本，根据明确偏好或系统偏好提前设置 `html.dark`，减少暗色主题首帧闪白。

## 错误处理与兼容性

- 封面上传失败不会清除当前封面；服务端拒绝不属于当前用户或不存在的资产。
- 旧比赛没有封面时所有视图均使用渐变占位；旧更新客户端不传封面字段时保留原值。
- 评分失败保留滑块当前值并显示接口消息，用户可重试；聚合与比赛得分只在评分事务内更新。
- 首页 Redis 不可用、缓存值损坏或写入失败时不影响响应；数据库无内容时返回空结构。
- 首页和侧栏在窄屏、暗色主题、无 `backdrop-filter`、键盘操作和 `prefers-reduced-motion` 下均有降级。

## 验证

实现后补充后端回归，覆盖封面所有权/保留/移除/响应、评分创建后更新及聚合、首页聚合结构与缓存回退。更新评分浏览器测试，使其验证首次提交后仍可修改。新增首页/主题侧栏浏览器测试，验证 Banner 高度、最新比赛/随机汤布局、主题开关 ARIA 与 `html.dark` 状态。最后运行后端完整 pytest、前端生产构建和目标 Playwright 测试。
