# 海龟汤社区社交平台扩展设计

更新日期：2026-08-08
状态：初步方案已确认，待书面规格复核

## 1. 目标与范围

本批改造把当前可构建的社区原型扩展为具备完整账户、个人主页、签到等级、提及通知、实时一对一聊天、根用户群发和邮件推广能力的社交平台，同时修复汤底展示、人数字段、邮箱验证和搜索问题。

实现继续使用 FastAPI、SQLModel、PostgreSQL、Vue 3、Pinia、Vue Router 和 Tailwind CSS。不会重写现有认证、内容和互动模块，也不会引入独立搜索服务或独立聊天服务。Redis 保持可选；核心 HTTP、数据库消息和签到功能在 Redis 不可用时仍可使用。

本批明确不做群聊、语音/视频、阅后即焚、自定义贴纸商店、邮件打开率追踪和富文本所见即所得编辑器。

## 2. 交付顺序与完成纪律

改造拆为六个可独立验收的任务：

1. 内容字段、汤底、根用户、邮箱验证、公开 URL 和搜索修复。
2. 用户设置、头像、密码、主题和个人主页。
3. 签到等级、代表作和 @ 提及通知。
4. 会话式私信、WebSocket 输入状态和 Emoji。
5. 根用户系统站内信、附件和批量邮件。
6. 全站视觉收敛、旧库最终迁移和端到端验收。

每个任务必须按测试先行完成，并在该任务的定向测试、后端回归和前端构建通过后立即更新 `HANDOVER.md`。交接手册记录实际命令、迁移状态、已知限制和下一任务，禁止等到所有任务结束后集中补写。

## 3. 内容与基础故障修复

### 3.1 汤底按需展开

所有已发布海龟汤的汤底都允许所有访问者查看，不再以作者或管理员身份作为权限条件。详情页首次请求固定返回 `solution: null`；用户点击“展开汤底”后再请求 `GET /api/turtle-soups/{soup_id}?reveal=true`，后端对任何访问已发布作品的用户返回汤底。作者和根用户进入页面时也遵循首次隐藏规则。

未发布、已删除或被隐藏的作品仍按内容可见性规则返回 404。前端按钮拥有加载、失败重试和已展开状态；重复点击不改变页面布局。

### 3.2 主要人物与次要人物

`Soup.main_player_count` 和 `Soup.secondary_player_count` 从整数列迁移为数据库 `TEXT` 列。创建和编辑表单使用 `type="text"`，不使用数字输入框、数字键盘、最小值或最大值校验。请求仍需包含两个字段，但不做非空、数值、范围或类别校验，允许数字、中文、Emoji、空字符串和其他 Unicode 文本；只受应用统一请求体大小上限约束。

旧整数数据使用数据库类型转换原样转为十进制字符串，例如 `2` 迁移为 `"2"`，不丢失作品或重置字段。

### 3.3 SkyUnreal 根用户

升级迁移按精确用户名 `SkyUnreal` 查找现有用户并把角色更新为 `root`，保留 UID、邮箱、密码、状态和全部关联数据。迁移重复执行不产生额外变更；找不到用户或出现不可能的重复用户名时明确报错，不创建同名替代账号。迁移报告只记录 UID、用户名和角色，不输出邮箱或凭据。

### 3.4 邮箱验证与公开地址

新增 `PUBLIC_WEB_URL` 配置，要求为完整 `http://` 或 `https://` 地址并去除尾部斜杠。验证邮件、密码重置邮件和站内通知邮件只用该配置生成浏览器链接；监听地址、Vite 代理和 CORS 不再被当成邮件链接来源。为兼容现有部署，未显式设置时读取旧 `APP_URL`，并在 `.env.example` 和交接手册中标记迁移方式。

邮箱验证接口改为幂等：

- 未使用且未过期的令牌激活账户并返回 200。
- 已使用且关联账户已激活的同一令牌再次提交仍返回 200 和“邮箱已验证”。
- 未使用但真正超时的令牌返回结构化 `VERIFICATION_EXPIRED`。
- 不存在的令牌返回结构化 `VERIFICATION_INVALID`。
- 两个并发请求通过事务和行锁保证最多一次状态转换，另一个请求得到幂等成功。

前端对同一 token 只保持一个在途请求，成功后不再被后续错误覆盖。真实数据库证据显示现有令牌在生成后约 37 秒即被消费，当前接口的第二次提交会立刻错误返回“无效或已过期”；回归测试必须覆盖这一双提交路径。

### 3.5 搜索

搜索继续提供 `/api/search/users`、`/posts` 和 `/turtle-soups`，但所有响应字段与页面统一：帖子返回 `excerpt`，海龟汤返回 `puzzle_excerpt`。后端在数据库执行过滤、排序、计数和分页，不先加载全部结果。

“全部”搜索在前端使用独立请求结果汇总。一个分类失败时仍显示其他分类并在失败分类内提供重试，不再因 `Promise.all` 的单点失败清空全部结果。导航搜索和搜索页同步 URL 查询参数，直接打开 `/search?q=...` 与页面提交得到相同行为。搜索结果标题、摘要、作者和目标链接均有契约测试。

## 4. 用户设置、主题和个人主页

### 4.1 用户设置

`User` 新增可查询的 `allow_bulk_email: bool = false`、`theme_preference: light|dark|system = system` 和 `token_version: int = 0`。设置页分为“个人资料”“账户安全”“通知与邮件”“外观”四个标签页：

- 个人资料：昵称、简介、头像上传和头像移除。
- 账户安全：使用旧密码修改新密码；新密码继续遵守现有 bcrypt 72 字节限制。
- 通知与邮件：站内通知偏好和 `allow_bulk_email` 开关。
- 外观：`light`、`dark`、`system` 三段式主题选择。

头像复用现有上传校验，只允许图片类型和 5 MiB 上限。服务端只接受当前用户已上传的对象键或明确移除头像，不能把任意外部 URL 写入头像字段。修改密码验证旧密码，成功后增加 `User.token_version`；access/refresh token 都携带版本，旧令牌随即失效。

`allow_bulk_email` 默认 `false`。它只控制根用户发起的批量通知和推广邮件，不影响注册验证、密码重置和安全告警，也不影响任何站内信或 @ 通知。

### 4.2 主题与视觉基线

浅色主题以白色页面、浅灰分隔线、黑灰正文为主；深色主题以黑色页面、近黑表面、灰白正文为主。蓝色用于主要操作，绿色用于成功，琥珀色用于提醒，红色用于危险操作；移除当前大面积紫色、蓝紫渐变和装饰性渐变。

主题在应用挂载前从本地偏好或系统偏好初始化，避免白屏闪烁。登录用户的选择同时保存到账户设置，本地值用于未登录访问和离线启动。

### 4.3 个人主页

浏览器路由固定为 `/profile/:uid`，公开 API 为 `GET /api/users/{uid}/profile`。公开资料只返回 UID、用户名、昵称、头像、简介、角色展示、等级、经验、注册时间、统计、关注关系、代表作和已发布海龟汤，不返回邮箱、通知偏好或其他账户字段。

个人主页按以下结构呈现：

- 头像、昵称、`@username`、`UID`、等级和简介。
- 本人看到编辑入口；其他用户看到关注和发消息入口。
- 最多 5 个代表作，按用户指定顺序显示。
- 已发布海龟汤按 `created_at DESC, id DESC` 分页展示。

新增 `FeaturedSoup(user_uid, soup_id, position)`，对 `(user_uid, soup_id)` 和 `(user_uid, position)` 建唯一约束。`PUT /api/users/me/featured-soups` 一次提交完整有序 ID 列表；只允许选择本人已发布作品，最多 5 个。作品变为不可见时自动从公开主页过滤，用户下次编辑时可移除失效项。

## 5. 签到与等级

现有 `User.points` 作为经验值继续保留，避免无意义的数据复制。公开 API 使用 `experience_points` 名称映射该列，并计算等级：

```text
level = min(100, 1 + floor(sqrt(experience_points / 100)))
当前等级起点 = 100 * (level - 1)^2
下一等级起点 = 100 * level^2
```

每日签到使用可配置 `SIGNIN_TIMEZONE`，默认 `Asia/Shanghai`。奖励沿用当前规则：基础 10 经验，加上 `min(连续签到天数, 7)`；中断一天以上后连续天数重置为 1。

`SigninRecord` 增加业务日期并对 `(user_uid, signin_day)` 建唯一约束，数据库约束负责防止并发重复签到。接口包括：

- `GET /api/users/me/signin`：今日状态、连续天数、经验、等级和下一等级进度。
- `POST /api/users/me/signin`：执行签到并返回本次奖励和更新后的等级信息。

已存在的积分、最后签到时间和连续天数原样保留；历史记录按配置时区回填业务日期。

## 6. @ 提及与通知

帖子、帖子评论、海龟汤评论的创建和编辑都解析 `@用户名`。语法为 `@` 前处于文本起点或空白边界，用户名后必须为空白或文本结尾，例如 `@G先生 所提供的内容`；紧连标点或正文的字符串不识别为提及。

新增 `Mention(actor_uid, mentioned_uid, target_type, target_id, created_at)`，对提及人、目标类型和目标 ID 建唯一约束。保存内容后在同一事务内解析现有用户名、写入缺失 Mention、删除编辑后消失的 Mention，并为新增提及创建 `NotificationType.MENTION`。不为提及自己生成通知，同一内容重复出现同一用户名只通知一次。

正文继续保存原始文本。前端使用安全的文本分词组件把有效 Mention 渲染为 `/profile/<uid>` 链接，不使用 `v-html` 拼接用户内容。用户名不存在时保留普通文本。通知中心展示提及者、摘要和原内容链接；这里属于站内通知，不进入用户私聊会话，也不受批量邮件偏好影响。

## 7. 会话式用户私信

用户私信采用一对一会话，不再使用收件箱/已发送邮件布局。新增 `DirectConversation` 保存规范化的两个用户 UID 和最后消息时间，现有 `private_messages` 增加 `conversation_id` 并继续作为持久消息表。迁移按每对用户回填一个会话，保留原消息 ID、发送者、接收者、已读和创建时间。

HTTP API 提供会话列表、历史消息分页、创建/查找会话、发送消息和已读游标。拉黑任一方向时禁止新发消息，但保留双方历史记录。会话列表按最后消息倒序，消息历史使用稳定游标分页。

WebSocket 使用 `/ws/messages`。连接后客户端必须在 5 秒内发送 `{type: "auth", token: "..."}`，避免把 JWT 放入 URL 和访问日志。服务端验证 access token 后支持以下事件：

- `message.created`：新消息及服务端 ID。
- `message.read`：对方已读到的消息 ID。
- `typing.start` 和 `typing.stop`：正在输入状态。
- `presence.error`：认证、权限或事件格式错误。

输入状态不写数据库，5 秒无更新自动过期；WebSocket 不可用时消息仍通过 HTTP 发送和轮询接收。多进程部署时使用 Redis Pub/Sub，同一进程开发环境使用内存连接管理器并在健康检查标记适配器状态。

消息正文支持 Unicode Emoji。前端提供分类 Emoji 面板并插入原生字符，不保存任意 HTML，也不实现自定义贴纸上传。聊天桌面布局为左侧会话列表和右侧消息流；移动端在列表与单个会话间切换。消息气泡、时间、已读状态、输入提示和发送失败重试不会改变主布局宽度。

## 8. 根用户系统站内信与批量邮件

系统站内信与用户私聊使用不同模型和页面。新增：

- `SystemMessage`：标题、Markdown 正文、创建者、创建时间和发送模式。
- `SystemMessageRecipient`：消息、接收用户、已读时间和投递时间。
- `MessageAttachment`：所属消息、原文件名、私有存储键、MIME、大小和哈希。
- `EmailCampaign`：主题、Markdown 正文、邮件类别、创建者和队列状态。
- `EmailCampaignRecipient`：活动、用户、目标邮箱快照、投递状态、尝试次数和错误摘要。

只有 `root` 可创建和发送系统站内信或批量邮件；普通管理员无权调用。收件人可选择任意多个用户或全部 active 用户。站内信不能退订，允许受限 Markdown 和最多 5 个附件；单附件最多 10 MiB，总计最多 25 MiB。附件允许 PNG、JPEG、GIF、WebP、PDF、TXT 和 ZIP，存放在非公开目录，通过鉴权下载接口校验接收者或根用户身份。

Markdown 后端禁用原始 HTML并生成经过允许列表清洗的预览；前端渲染再次禁止脚本、事件属性和危险协议。站内信保存时展开接收人快照，保证“全部用户”不会把以后注册的用户追加到旧消息。

批量邮件分为“通知”和“推广”，两者都只允许选择 `allow_bulk_email=true` 的 active 用户。根用户选择器中拒收用户显示为禁用且无法勾选；“全部用户”由后端再次过滤，不能信任前端。验证、重置密码和安全邮件不经过此过滤。

发送邮件不在 HTTP 请求内循环调用 SMTP。API 创建持久化发件队列，后台工作器逐个发送、记录结果并有限重试；进程中断后 pending 项可继续执行。邮件正文使用同一受限 Markdown 渲染器，可附带符合相同限制的附件。每次群发、重试和取消都写入 `OperationLog`，错误日志不得包含正文、附件内容、完整邮箱或 SMTP 凭据。

## 9. 数据迁移

在任何真实数据库写入前执行 `pg_dump`，备份文件放在 Git 忽略的运行时备份目录并记录文件名、时间和校验和。迁移脚本必须支持 `--dry-run`、重复执行、动作计数和事务失败回滚。

迁移按任务逐步完成，最终脚本至少覆盖：

1. 人数整数列转文本并保留值。
2. `SkyUnreal` 角色升级为 root。
3. 用户 token 版本、主题和批量邮件偏好默认值。
4. 签到业务日期和唯一约束。
5. 代表作、Mention 和通知关联表。
6. 旧私信会话回填和会话唯一约束。
7. 系统消息、私有附件和邮件队列表。

新表和新列先以兼容默认值加入，数据回填后再增加非空或唯一约束。迁移前后核对各核心表行数、UID 范围、外键孤儿数和重复键数量。当前真实库只有一个已激活的 `SkyUnreal` 用户、无帖子和海龟汤，但脚本必须按存在历史内容和消息的通用旧库设计。

## 10. 错误处理与安全

新增接口统一返回 `detail: {code, message}`。前端展示 `message`，日志和测试使用稳定 `code`。批量操作返回已选择、已过滤、已排队和失败计数，不把部分失败伪装为整体成功。

安全边界包括：

- 根用户接口只接受 `root`，不把 `admin` 当作等价角色。
- 公开个人主页不泄露邮箱、偏好、令牌版本和处罚信息。
- 头像和附件校验 MIME、扩展名、大小与所有权。
- Markdown、提及和聊天正文均不信任 HTML。
- WebSocket 复用 access token 类型、角色、状态和 token 版本校验。
- 群发邮件严格执行服务端 opt-in 过滤和审计。
- 签到、提及、代表作、会话和收件人快照使用数据库唯一约束保证幂等。

## 11. 前端信息架构与响应式验收

全站使用固定高度图标按钮、稳定网格轨道和一致表单高度；使用现有 Heroicons，不手绘重复 SVG。页面区段使用无边框布局和分隔线，卡片只用于重复内容、消息项和对话框，不嵌套卡片。

设置页在桌面使用紧凑侧边标签，移动端使用顶部横向标签。个人主页首屏直接展示身份、UID、等级和操作，不做营销式 Hero。系统收件箱与用户聊天在导航中分开命名为“系统消息”和“私信”。根用户后台增加“系统消息”和“邮件群发”入口。

浏览器验收覆盖 375x812、768x1024、1440x900，并检查长用户名、超长人物文本、五个代表作、空会话、长消息、Emoji、附件文件名、Markdown、正在输入提示和深浅主题。任何文字不得溢出按钮、头像区、消息气泡或导航。

## 12. 测试与验收

每个任务采用 RED-GREEN-REFACTOR：先加入能复现旧行为的失败测试，再做最小实现。后端至少覆盖：

- 汤底匿名展开和默认隐藏。
- 人物字段任意文本及旧整数迁移。
- SkyUnreal 根角色迁移幂等。
- 邮箱首次成功、双提交幂等、真实过期和公开 URL。
- 三类搜索字段、分页和部分失败契约。
- 头像所有权、修改密码后令牌失效和批量邮件偏好。
- 个人主页隐私、时间排序和最多五个代表作。
- 签到并发唯一性、时区边界和等级公式。
- 提及语法、去重、编辑差异和安全链接渲染数据。
- 私信迁移、拉黑权限、WebSocket 认证、消息和 typing 事件。
- 系统消息权限、Markdown 清洗、附件鉴权和邮件 opt-in 过滤。
- 发件队列重试、恢复和审计。

前端执行类型检查和生产构建，并新增 Playwright 关键流程与三视口截图。最终验收命令包括完整 pytest、compileall、前端 build、Playwright、迁移 dry-run、备份、真实 PostgreSQL 迁移和迁移后数据核对。只有命令产生新鲜成功输出的项目才可在交接手册标记完成。
