# 评分锁定与比赛自定义关键词设计

## 目标

本次改动包含两项独立但范围明确的功能：

1. 海龟汤详情页使用滑块选择评分，并在二次确认后永久锁定；所有历史评分也立即锁定。
2. 比赛发布页允许管理员在选择已有标签之外新增关键词；新关键词保存为全局自定义标签，可供之后的海龟汤和比赛复用。

不改变评分范围、比赛收录规则或标签的全局数据模型。评分仍为 1 到 10 分、0.5 步进；参赛作品仍按命中任一比赛关键词收录。

## 评分交互

未评分用户看到 1 到 10、步进 0.5 的滑块，初始草稿值为 5.0。滑动时只更新页面上的分值，不发送请求。点击“确认评分”后打开二次确认弹窗，明确显示待提交分值和“提交后不可修改”的提示。

用户确认后提交评分。请求期间禁用滑块和确认操作，防止重复提交。成功后使用响应中的 `my_rating` 更新详情，滑块保持该分值并禁用，页面显示“已评分 X 分，评分已锁定”。取消弹窗不会提交或锁定。

详情响应中 `my_rating` 非空时，页面从首次渲染开始即进入锁定状态。因此历史评分不需要迁移，也没有修改入口。弹窗使用项目现有 Headless UI 能力处理遮罩、Escape、焦点圈定和关闭后的焦点恢复。

## 评分接口与一致性

保留 `PUT /api/turtle-soups/{soup_id}/rating`，以兼容现有客户端，但语义改为首次写入成功、之后不可修改。

后端先按 `(user_uid, soup_id)` 查询评分。已有记录时返回 HTTP 409：

```json
{
  "detail": {
    "code": "RATING_ALREADY_SUBMITTED",
    "message": "评分确认后不可修改"
  }
}
```

首次写入继续依赖 `uq_ratings_user_soup` 唯一约束。并发请求发生唯一约束冲突时，后端回滚嵌套事务并返回相同的 409，绝不读取草稿分值覆盖数据库中的旧值。只有新增成功后才刷新作品平均分和评分人数。

收到普通提交错误时，前端保留草稿值并显示后端消息。收到 409 时，说明服务端已有确定评分，前端重新加载详情并以服务端 `my_rating` 进入锁定状态。未登录、自评和非法分值沿用现有鉴权及校验错误。

## 比赛关键词交互

比赛发布页保留已有标签复选项，并在同一区域增加“新增关键词”输入和添加按钮。用户可以按 Enter 或点击按钮将文本添加为待创建关键词，并可在提交前逐个移除。

已有标签和新关键词统一计数，合计至少 1 个、最多 10 个。前端对完全相同的输入去重并给出即时数量限制；后端仍执行最终规范化、去重和数量校验。发布按钮不再因标签列表为空而永久禁用，只要已有选择或新增关键词满足要求即可提交。

## 比赛接口与标签复用

`CompetitionCreate` 增加 `custom_tags: list[str]`，前端 `CompetitionCreate` 类型同步增加 `custom_tags: string[]`。原有 `required_tag_ids` 保持兼容，校验从“字段自身至少一个 ID”调整为“已有 ID 与自定义名称解析后至少一个标签”。

提取共享标签解析服务，供海龟汤发布和比赛发布使用。服务负责：

1. 校验已有标签存在且为 `active`。
2. 使用现有 `normalize_tag_name` 执行 NFKC、空白折叠、长度、控制字符和 HTML 校验。
3. 按规范化 slug 查询全局标签；启用的同名标签直接复用，停用的同名标签拒绝使用。
4. 不存在的名称创建 `kind=custom`、`status=active` 的全局标签。
5. 对已有 ID 和新名称解析出的 ID 去重，并限制总数为 1 到 10。

比赛标签解析、标签创建和比赛创建在同一个数据库事务中完成。任何校验或数据库操作失败都不提交标签或比赛，避免产生孤立标签。响应仍以最终的 `required_tag_ids` 返回所有比赛关键词 ID，不新增第二套存储字段。

## 边界与错误

- 重复评分统一返回 409，不把重复提交视为幂等成功，因为客户端必须明确知道评分没有被修改。
- 并发首次评分只允许一个请求成功，另一个请求返回 409，数据库中保留先成功的分值。
- 标签名称规范化后重复时只使用一个全局标签和一个比赛关键词 ID。
- 引用不存在、停用或非法的标签时返回结构化 422，整个比赛创建事务回滚。
- 关键词总数超过 10 或解析后为空时返回结构化 422。
- 比赛作品收录仍使用现有任一标签命中逻辑，不在本次改动中切换为全部标签命中。

## 测试策略

实施遵循测试先行。

后端评分测试覆盖：已有评分再次提交返回 409；原分值、平均分和人数不变；首次评分成功；唯一约束并发冲突不覆盖已提交值；历史评分仍通过详情 `my_rating` 返回。

后端比赛测试覆盖：只使用新关键词创建比赛；同名全局标签被复用；已有 ID 与新名称规范化后去重；新标签为启用的 `custom` 标签；无效、停用、空集合和超量关键词导致比赛与新标签整体不提交。共享解析服务的规范化规则继续由单元测试覆盖。

前端 Playwright 测试覆盖：滑块范围和步进；拖动不自动提交；二次确认取消与确认；成功后锁定；历史评分初始锁定；409 后重新加载并锁定；比赛页添加、删除、去重新关键词并随创建请求提交。

最终验证运行相关后端测试、完整后端测试、前端类型检查与生产构建、Playwright 关键流程，并检查桌面与移动视口中评分控件、弹窗和关键词区域不存在溢出或重叠。
