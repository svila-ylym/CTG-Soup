# 海龟汤社区系统可用性收尾设计

更新日期：2026-08-08

## 1. 目标与边界

目标是让当前原型在本机可运行并具备可验收的核心工作流：注册/登录、海龟汤发布与互动、比赛收录、公告、帖子/评论、社交、私信、通知、搜索和后台基本管理。验收包括后端契约测试、前端生产构建和关键 HTTP/浏览器集成测试。

不自动执行真实 SMTP 授权码、云存储、公网部署或生产运维；Redis、Elasticsearch、Celery 和 WebSocket 在本机提供可选适配器、健康检查和无依赖降级，核心功能不能因这些服务未启动而崩溃。

## 2. 分阶段交付

### 阶段 A：共享契约与数据可靠性

补齐独立 Schema、统一 FastAPI `detail` 错误、OpenAPI 路由快照、SQLite 集成测试夹具和可重复迁移入口。为评分、点赞、收藏、关注、黑名单、比赛收录增加数据库唯一约束；为本地服务增加健康检查和启动诊断。

### 阶段 B：比赛、标签治理与公告

比赛统一使用 `creator_uid`、`required_tag_ids`、`score_type`、结算快照和唯一收录。发布/编辑海龟汤后按 active 标签和比赛时间范围自动收录，重复操作幂等，已结算比赛固定快照。管理员可创建、发布、停用、改名、合并标签，并管理公告草稿/发布/撤回；公告正文只保存纯文本或消毒后的受限 Markdown。

### 阶段 C：旧字段模块治理

逐个重写帖子、社交、私信、成就和搜索路由的请求/响应 Schema，统一 `uid` 后缀字段，移除 `User.id`、`author_id`、`sender_id`、`is_active` 等不存在字段访问。每个模块完成后补 HTTP 契约测试和前端类型，不增加过渡别名。

### 阶段 D：评论与前端工作流

实现海龟汤评论、回复、分页、作者/管理员删除和状态过滤；补齐消息、帖子、通知、比赛、搜索和后台 8 个空 Vue 页面。页面必须有加载、空、错误和提交状态，公告条位于导航下不遮挡内容，导航/筛选/发布表单在 375、768、1440 宽度下不横向溢出。

### 阶段 E：限流、重试与集成验收

邮箱验证增加 Redis/IP/邮箱维度限流、异步发送重试和失败可重试状态。编写关键浏览器流程：注册验证、登录、发布带元数据的海龟汤、筛选/揭示/评分、比赛收录、评论、私信、公告和管理员操作。服务缺失时健康检查明确报告 degraded，核心 API 使用安全降级。

## 3. 数据与 API 约束

- 所有公开响应使用规范 `uid`、`author_uid`、`creator_uid`、`sender_uid`、`receiver_uid`、`average_score`、`rating_count` 和 `favorite_count`。
- 所有新建/更新接口使用独立 Pydantic Schema；数据库模型不直接作为输入契约。
- 竞赛收录唯一键为 `(competition_id, soup_id)`；互动唯一键按用户、目标类型和目标 ID 组合定义。
- 管理修改写入操作日志；标签、公告、评论文本拒绝未消毒 HTML。
- 迁移脚本支持 dry-run、计数报告、备份说明和重复执行；生产执行前必须备份。

## 4. 验证策略

- 后端：pytest 全量、模块契约/权限/并发测试、compileall、OpenAPI 快照。
- 前端：`vue-tsc -b`、`npm run build`、关键页面的组件/路由测试和三视口浏览器检查。
- 集成：SQLite 用于确定性 API 测试；PostgreSQL/Redis/SMTP/搜索服务存在时运行真实适配器测试，不存在时运行降级路径测试。
- 每个阶段完成后更新 `HANDOVER.md`，只标记有新鲜命令输出证明的项目。

## 5. 明确不做的替代方案

不采用一次性重写所有后端模块，也不在前端先堆页面再猜 API；不通过继续增加旧字段别名来掩盖契约错误，不用无业务含义的空 Vue 模板绕过构建。
