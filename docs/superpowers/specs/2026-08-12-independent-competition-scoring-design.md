# 独立评审比赛评分设计

## 目标

比赛新增“独评”评分方式。独评比赛不使用用户对海龟汤的公开评分；比赛结束并到达配置的评分日期后，由比赛创建者或管理员逐项录入比赛方评分。全部参赛作品完成评分后才能结算，结算时一次性公开最终分数和排行。

## 已确认规则

- 评分方式包括现有“平均分”和新增“独评”。
- 独评分数范围为 1 至 10，必须是 0.5 的倍数。
- 独评比赛必须配置单个 `scoring_at` 评分日期，表示允许开始录入比赛方评分的时间。
- `scoring_at` 不得早于比赛结束时间。
- 仅比赛创建者和管理员可以查看、录入或修改未结算的独评分数。
- 未到 `scoring_at` 不允许录入。
- 每一件参赛作品都必须有独评分数，比赛才能结算；未评分不等于 0 分。
- 结算前公众只能看到参赛作品和“等待比赛方评分”，不能看到独评分数、完成度或临时排行。
- 结算后公开最终分数、总排行及可选标签分组排行。
- 同分仍按作品发布时间由旧到新排序，再以作品 ID 保证稳定顺序。
- 管理员保留代录和结算权限。

## 数据模型

### Competition

- 扩展 `CompetitionScoreType`，新增 `INDEPENDENT = "independent"`。
- 新增可空字段 `scoring_at: datetime | None`。
- 平均分比赛的 `scoring_at` 必须为空。
- 独评比赛的 `scoring_at` 必填且不得早于 `end_time`。

### CompetitionEntry

- 新增 `judge_score: float | None`，保存未结算的私有比赛方评分。
- 新增 `judged_by_uid: int | None`，记录最后一次保存评分的用户。
- 新增 `judged_at: datetime | None`，记录最后一次保存时间。
- 现有 `final_score` 继续作为公开及快照使用的最终分数。独评结算前不从 `judge_score` 同步到 `final_score`；结算时才复制并冻结。

这样可以明确区分“未评分”和真实分数，也避免公开比赛详情通过现有 `final_score` 提前泄露比赛方评分。

## 迁移与兼容

新增可重复执行的比赛独评迁移：

- 给 `competitions` 增加可空 `scoring_at`。
- 给 `competition_entries` 增加可空 `judge_score`、`judged_by_uid`、`judged_at`。
- `judged_by_uid` 引用 `users.uid`，删除用户时保留评分但将操作者置空。
- 不修改旧比赛的 `score_type`。所有旧数据继续按平均分运行。
- 迁移接入 `app.migrations.social_platform --phase all`，重复运行无动作。

## API 与权限

### 创建和编辑比赛

`CompetitionCreate` 和 `CompetitionUpdate` 接受：

- `score_type: "average" | "independent"`
- `scoring_at: datetime | null`

统一校验评分方式、比赛时间和评分日期。独评必填评分日期且不得早于结束时间；平均分拒绝非空评分日期，避免保存无效配置。

比赛未结算且没有任何独评分时，可修改评分方式、日期及影响参赛集合的配置。一旦任一参赛作品已有 `judge_score`，禁止：

- 修改 `score_type` 或 `scoring_at`；
- 修改比赛起止时间、必选/可选标签；
- 执行会重建参赛集合的编辑。

仍允许修改不影响评分对象的比赛名称、说明、竞赛色和获奖名额。已结算比赛继续完全禁止编辑。

### 评分工作台

新增受保护接口：

- `GET /api/competitions/{competition_id}/judging`
- `PUT /api/competitions/{competition_id}/entries/{entry_id}/judge-score`

仅比赛创建者或管理员可用。工作台返回参赛作品、作者、私有评分、最后评分人、评分时间、已评分数和总数。录分接口接受 `{ "score": number }`，校验时间、比赛状态、参赛关系和 1 至 10 的 0.5 倍数。

创建者和管理员都可覆盖现有分数；覆盖后更新 `judged_by_uid` 和 `judged_at`。结算后拒绝修改。

### 公开详情

- 平均分比赛继续显示实时排行。
- 独评未结算时 `rankings` 返回空总榜和空分组榜，参赛作品的公开 `final_score` 不包含私有评分。
- 公开响应增加评分方式和评分日期，前端显示“独评”和评分日期；未结算时显示“等待比赛方评分”。
- 独评结算后从现有 `result_snapshot` 返回公开排行。

### 结算

平均分结算保持现状。独评结算额外要求：

- 当前时间不早于 `scoring_at`；
- 比赛已经结束；
- 每个 `CompetitionEntry.judge_score` 均非空。

缺少评分时返回冲突响应，并包含未评分数量，不将缺失项当作 0 分。满足条件后在同一事务中：

1. 将每个 `judge_score` 写入对应 `final_score`。
2. 按最终分数降序、作品发布时间升序、作品 ID 升序生成总榜和分组榜。
3. 写入参赛记录的最终名次。
4. 生成现有结构的 `result_snapshot` 并写入 `settled_at`。

## 前端体验

- 创建和编辑页把只读“平均分”改为评分方式分段控件：“平均分 / 独评”。
- 选择独评时显示“评分日期（UTC+8）”单个日期时间输入，并在提交前校验不早于结束时间。
- 详情页显示实际评分方式；独评未结算时隐藏分数和榜单，展示参赛作品以及“等待比赛方评分”。
- 对比赛创建者和管理员显示“比赛方评分”入口。评分工作台使用表格逐项输入分数，展示完成度并允许保存修改。
- 全部评分完成且时间条件满足时显示结算按钮；服务端仍执行最终完整性校验。
- 结算后工作台只读，公开详情展示最终总榜和分组榜。

## 错误处理与审计

- 时间未到、比赛未结束、权限不足、分数非法、作品不属于比赛、评分不完整和比赛已结算均使用稳定错误码。
- 评分保存写入 `judged_by_uid` 和 `judged_at`；结算沿用比赛结果快照作为最终审计记录。
- 私有独评分数只出现在受保护的工作台响应中，不加入公开比赛或海龟汤响应。

## 验证范围

用户要求不采用 TDD；实现完成后进行聚焦验证：

- Schema 的评分方式和日期组合校验。
- 创建、编辑及旧客户端平均分兼容。
- 创建者、管理员和无权限用户的评分接口权限。
- 时间门禁、分数范围和 0.5 步进。
- 私有评分不出现在公开详情。
- 未全部评分时拒绝结算。
- 独评忽略用户平均分，并按独评分数生成总榜和分组榜。
- 同分由旧到新排序，结算快照稳定。
- 数据库迁移 dry-run、执行和幂等性。
- 前端类型检查和生产构建。
