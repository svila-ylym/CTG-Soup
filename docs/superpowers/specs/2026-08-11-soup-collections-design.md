# 海龟汤合集与 1.4.0 版本设计

## 目标

为作者提供公开的海龟汤合集功能，使同一系列的作品能从个人主页、发布/编辑表单、汤详情和合集详情页互相关联。每碗汤最多属于一个合集，合集内作品按发布时间由旧到新展示。应用版本从 `1.3.1` 更新为 `1.4.0`。

本功能只提交 GitHub Pull Request，不连接或修改部署服务器。

## 核心规则

- 合集归属于一个用户，包含名称、可选简介、创建时间和更新时间。
- 合集名称去除首尾空白后必须为 1–100 个字符；简介为纯文本，最多 2000 个字符。
- 一碗海龟汤最多属于一个合集，也可以不属于任何合集。
- 汤只能加入其作者本人创建的合集；合集作者和汤作者必须一致。
- 合集内只公开展示状态为 `published` 或 `revealed` 的汤，并按 `created_at`、`id` 由旧到新稳定排序。
- 空合集对作者本人可见，其他用户在列表和详情接口均不可见。
- 删除合集只解除所有汤的合集归属，不删除或改变汤的公开状态。
- 合集关联不会改写汤名，也不会自动添加 `合集名：` 前缀。

## 数据模型

新增 `SoupCollection` 模型和 `soup_collections` 表：

- `id`: 主键。
- `owner_uid`: 指向 `users.uid` 的外键并建立索引。
- `name`: 最长 100 个字符。
- `description`: 最长 2000 个字符的纯文本，默认空字符串。
- `created_at`、`updated_at`: UTC 时间。

在 `soups` 表新增可空的 `collection_id`，指向 `soup_collections.id` 并建立索引。外键使用 `ON DELETE SET NULL`；应用层删除合集时也会在同一事务内显式解绑相关汤，确保不同数据库环境的行为一致。

后端不得继续使用现有的 `Collection` 名称。该名称当前是收藏模型 `Favorite` 的兼容别名，新功能统一使用 `SoupCollection`，避免合集与收藏语义冲突。

## 迁移

新增幂等迁移模块，负责：

1. 创建 `soup_collections` 表及所有权索引。
2. 为 `soups` 增加可空的 `collection_id` 列、索引和外键。
3. 保留所有旧汤，旧数据的 `collection_id` 均为 `NULL`。

迁移必须支持 dry-run，在 dry-run 中只报告动作、不执行 DDL。该迁移接入 `app.migrations.social_platform` 的 `foundation` 阶段，使现有 `Update.sh` 和 `dev.sh migrate` 能自动发现并应用它。

## API

新增 `/api/collections` 路由和独立 schemas。

### 管理接口

- `POST /api/collections`: 登录用户创建合集。
- `PUT /api/collections/{collection_id}`: 仅作者修改名称和简介。
- `DELETE /api/collections/{collection_id}`: 仅作者删除合集并解绑所有汤，成功返回 204。
- `GET /api/collections/mine`: 返回当前用户的全部合集，包含空合集，供汤编辑器选择。接口分页，每页最多 100 条。

所有写接口在数据库提交失败时回滚。对不存在的合集返回 404，对非作者操作返回 403，对字段错误返回 422。

### 公开接口

- `GET /api/collections?owner_uid=<uid>&page=<n>&page_size=<n>`: 获取指定用户的合集。作者本人可见空合集，其他用户只看到至少含一碗公开汤的合集。
- `GET /api/collections/{collection_id}?page=<n>&page_size=<n>`: 返回合集、作者摘要以及分页作品。空合集仅作者本人可访问，其他用户收到 404。

合集摘要包含 `id`、`owner_uid`、`name`、`description`、公开作品数和时间字段。合集详情中的作品摘要包含汤 ID、标题、谜面摘要、流派、汤色、平均分、评分数、点赞数、比赛边框色和发布时间。

静态路由 `/mine` 必须在 `/{collection_id}` 之前注册，避免被解析为数字 ID。

### 汤接口扩展

- `SoupCreate` 新增 `collection_id: int | null = null`。
- `SoupUpdate` 新增可显式设为 `null` 的 `collection_id`。
- `SoupResponse` 新增 `collection`，值为 `{ id, name, owner_uid }` 或 `null`。

创建或更新汤时，后端先验证合集存在且属于当前汤作者。其他用户的合集返回 403，不存在的合集返回 422。更新传入 `null` 时将汤移出合集；未提交该字段时保持当前归属不变。

## 前端交互

### 个人主页

在“代表作”和“已发布海龟汤”之间增加“合集”区：

- 所有人可以查看该用户的公开合集。
- 作者本人可以看到空合集，并通过“创建合集”按钮新增合集。
- 创建和编辑使用紧凑弹窗，字段为名称和简介。
- 作者使用图标按钮编辑或删除合集；图标具有 tooltip 和无障碍名称。
- 删除前显示确认信息，明确说明合集内海龟汤不会被删除。
- 列表分页独立于主页的汤分页；删除当前页最后一项后回退到有效页。

保存、删除期间禁用重复提交。请求失败时保留已有列表和表单内容，并显示内联错误。

### 发布和编辑汤

`SoupEditorForm` 加载 `GET /api/collections/mine`，显示一个合集选择菜单：

- 第一项固定为“不加入合集”。
- 其余选项显示当前作者的所有合集，包括空合集。
- 发布和编辑均可选择、切换或移出合集。
- 下拉加载失败不阻断汤表单其他字段，显示局部错误并允许重试。

草稿快照增加 `collection_id`。恢复旧格式草稿时缺失值规范化为 `null`，不会产生无效提交。

### 汤详情

汤详情在作者及元数据区域显示“来源于「合集名」合集”。该文本链接到 `/collections/{id}`。没有合集时不显示占位内容。

### 合集详情

新增公开路由 `/collections/:id`：

- 首屏显示合集名称、作者链接、简介和公开作品数。
- 作品列表使用稳定的纵向布局，按发布时间由旧到新排列并支持分页。
- 每项显示汤名、谜面摘要、流派、汤色、分数和发布时间；点击进入汤详情。
- 作者查看空合集时显示可执行的空状态，并提供“发布海龟汤”入口。
- 访客访问不存在、已删除或对其不可见的空合集时显示 404 状态。

## 前端类型与客户端

新增 `SoupCollectionSummary`、`SoupCollectionDetail`、`SoupCollectionInput` 和合集汤摘要类型。新增 `collectionApi` 封装列表、详情、创建、更新和删除请求。

`TurtleSoup`、`SoupCreate`、`SoupEditorState` 和草稿类型同步增加合集字段。个人主页的合集请求独立于原有 `PublicProfile` 响应，避免扩大个人主页单一接口的职责和查询成本。

## 版本

仓库根目录 `VERSION` 是运行时版本唯一来源，将其从 `1.3.1` 更新为 `1.4.0`。页脚、健康接口和 OTA 状态会通过现有读取逻辑自动显示新版本，不新增重复版本常量。

## 测试与验收

后端测试覆盖：

- 迁移 dry-run 不写库、实际迁移可重复执行、旧汤保持未归属状态。
- 合集字段验证、创建、修改、所有权限制和删除解绑。
- 作者与访客对空合集的不同可见性。
- 合集只返回公开汤，并按 `created_at`、`id` 由旧到新排序。
- 汤创建、编辑、移出合集，以及跨用户合集和不存在合集的拒绝行为。
- 汤详情响应返回正确的合集摘要。

前端执行 Vue/TypeScript 类型检查和 Vite 生产构建。后端执行合集聚焦测试、迁移测试和全量 pytest；同时执行 Python compileall、Shell 语法、`git diff --check`，并确认 `VERSION` 精确等于 `1.4.0`。

验收完成后提交独立 GitHub PR。不得连接 SFTP/SSH、运行远端迁移、重启 Screen 或修改部署目录。
